🎯 Modernized Application Product & Testing Guide

                    
This modernized cloud-native runtime transforms legacy IBM Mainframe COBOL, BMS mapsets, and VSAM/DB2 constructs into an autonomous Spring Boot 3.3.4 microservice stack running on Java 21 LTS with PostgreSQL.

                


                

                    
🧪 Step-by-Step Business Logic Testing Guidelines

                    
Follow these standard test patterns to validate that modernized Java services faithfully execute the legacy business rules:


                    

                        
1

                        

                            
Select the Program & Rule in the Tester

                            
Navigate to the Interactive Business Rule Tester. Choose the target program from the dropdown. All business rules extracted by Agent 04 will populate automatically with their rule statements and legacy COBOL source citations.

                        

                    


                    

                        
2

                        

                            
Execute Positive Validation Scenarios

                            
Provide valid operational inputs (or click Set Valid Values). Click Execute & Verify Rule. Verify that the response badge indicates EXECUTED (HTTP 200) and that storage balances or status flags update to expected values in the Changed Working-Storage Variables table.

                        

                    


                    

                        
3

                        

                            
Execute Negative & Boundary Conditions

                            
Click Set Boundary Values or enter edge cases (e.g. requesting transaction amounts exceeding account balance + overdraft allowance, or negative values). Execute the rule and verify that guard logic triggers proper rejection badges (e.g. DATA_ERROR (HTTP 422)) without unhandled exceptions.

                        

                    


                    

                        
4

                        

                            
Inspect Legacy Source Citations

                            
Every business rule references its exact provenance in the legacy source (e.g. CBACT01C.cbl:142-168). Compare the runtime results with the cited COBOL condition-action branch to confirm deterministic parity.

                        

                    


                    

                        
5

                        

                            
Real-Time Database Verification

                            
Switch to the Real-Time Database Explorer tab to inspect live migrated PostgreSQL tables and data rows. After testing business rules or transactions that mutate data, verify that changes are persisted to the database in real time with complete schema fidelity.

                        

                    

                


                

                    
📡 Direct API Testing Endpoints

                    
All business rules, programs, and database tables are directly accessible via REST for automated testing and CI/CD validation:

                    
# 1. Fetch All Programs
GET  /api/v1/programs

# 2. Fetch All Extracted Rules
GET  /api/v1/rules

# 3. Execute a Specific Rule
POST /api/v1/programs/{programId}/rules/{ruleId}/execute
Content-Type: application/json
{
  "ACCT-BALANCE": 1500.00,
  "TX-AMOUNT": 200.00
}

# 4. Submit a BMS Screen Transaction
POST /api/v1/screens/{mapsetName}/submit
Content-Type: application/json
{
  "aid": "ENTER",
  "fields": { "ACCTNO": "10000000001" },
  "commarea": {}
}

# 5. Check Live Database Status
GET  /api/v1/database/status

# 6. List Migrated Tables & Columns
GET  /api/v1/database/tables

# 7. Query Live Table Rows
GET  /api/v1/database/tables/{tableName}/data?limit=50&offset=0

# 8. Interactive SQL Inspection
POST /api/v1/database/query
Content-Type: application/json
{
  "sql": "SELECT * FROM transtbl LIMIT 10"
}
